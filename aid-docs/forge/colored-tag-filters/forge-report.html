Colored tag filters

The tag/search redesign is specific enough for downstream planning. This session settled behavior; application implementation is a subsequent task.

Locked decisions

  • Full tags remain visible in link rows. Automatic persistent colors are consistent across folders, row labels, available tags, and selected tags, including tags on disabled links.
  • Show tags replaces Show hidden links and reveals one horizontally scrollable tag row below search and the button.
  • The available pool includes every tag in the current subtree, including hidden leaves, minus selected tags. Search results do not shrink the pool.
  • Tap an available tag to move it beside search into a horizontally scrollable selected-tag row. Tap a selected tag to remove the filter and return it.
  • Selected tags combine with AND. Free text further narrows those results using the existing broad substring search.
  • Typed tags begin with #. Space, comma, or Enter commits a known tag and removes the token and delimiter. Unknown tags stay in search with “Tag not found.”
  • Tag names reject whitespace and commas with clear guidance. Existing affected tags must be renamed explicitly.
  • Only selecting hidden, broken, or disabled permits matching hidden links and ancestors to appear; all selected tags and free text still apply.

Rejected options and reasons

  • Dots and hover-only labels: reconsidered by the user; keep full tags visible.
  • OR filtering: results must match both tags, rather than either.
  • Space-containing tags: spaces must commit typed tags; commas are also forbidden to avoid delimiter ambiguity.
  • Manual color configuration: user chose automatic persistent colors.
  • Grayscale-only disabled tags: consistent tag colors take precedence for labels; disabled codes and actions still indicate state.
  • Silently accepting unknown tags or renaming invalid tags: errors stay visible and corrections are explicit.
  • Result-dependent tag choices: a steady available pool keeps filters accessible, including after zero results.

Weak points carried into implementation

  • Many tags cannot be reliably distinguished by color alone. Visible labels remain essential; the palette must remain readable in light and dark themes.
  • Search and the selected-tag row compete for narrow-screen space. Preserve usable search and horizontally scrollable tag controls on mobile and by keyboard.
  • The no-whitespace/no-comma rule changes existing validation. Check actual link data and update conflicting documentation explicitly.
  • Exact palette, duplicate-token feedback, and filter reset behavior were not separately decided in this session.
