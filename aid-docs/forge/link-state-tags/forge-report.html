Link-state tags

Special-rule tags survived scrutiny as a unified way to filter and maintain link states. This is a planning outcome; implementation has not started.

Locked decisions

  • Reserve exact, case-insensitive hidden, broken, and disabled tags. Other tags stay descriptive.
  • Hidden keeps existing default omission and revealed opacity. Broken warns with an orange-red tint but still forwards. Disabled is grey and fully stops forwarding, Open, Download, and script execution; its short URL shows an explanation.
  • Disabled grey takes precedence over broken tint; hidden opacity applies independently. Readable tags communicate states without relying only on color.
  • Whole-tag #tag search is case-insensitive. Explicit state searches reveal matching hidden links and hidden-only ancestors; clearing search restores normal visibility. Ordinary text searches retain broad matching and respect the hidden toggle.
  • Migrate existing hidden booleans to tags, preserve other tags, remove false values, and reject the retired property with useful guidance.
  • The first implementation covers manual tags and their behavior. The automated checker is separate.
  • Future automation can overwrite any broken tag based on its latest check. Broken detection must not automatically hide links. Disabled is user-assigned; hidden may be assigned by users or automation.

Rejected and why

  • A toggle per state: shared tag search supplies the desired filtering without multiplying controls.
  • Keeping both a hidden property and hidden tag: two conventions make maintenance ambiguous.
  • Tracking manual versus automated ownership: deliberately omitted to keep the model simple.
  • Automatically hiding newly broken links: reconsidered and withdrawn by the user.

Weak points and deferred decisions

  • Tags now control behavior: removing disabled reactivates a link. Reserved-name rules must be explicit.
  • A successful automated check may remove a manual broken warning; this is an accepted tradeoff. Failure, timeout, recovery, and false-positive policies remain undefined.
  • All-hidden directories currently hide search. State search must remain reachable there to deliver the agreed filtering behavior.
  • Multi-term search syntax, disabled explanation copy, and copying interactions remain unspecified. Exact colors need accessible rendered verification.
  • Disabled blocks shl-provided paths; public destinations and previously downloaded launchers cannot be revoked by a tag.
  • Shared filtering alone does not require behavioral tags; separate fields could also feed search. Tags were retained for the user's combined goals of a unified editing model, filtering, and future automation.

Voices that pressure-tested the idea

🎯 Yui — The Craftsman: “One convention, fixed rules, no general-purpose engine.” Challenged descriptive labels becoming commands and duplicate hidden conventions.

🌶️ Boundary — Edge-Case Hunter: “Walk every path.” Exposed hidden-search exclusions, conflicting visual states, and script-launcher bypasses.

🚢 Dana — The Pragmatist: “Separate the checker from the states.” Kept automation out of the first implementation.

🧭 Mara — generated maintainer perspective: “Let me find the state and trust what it means.” Tested editing consequences, search expectations, and automated removal of manual warnings.
