idea: Use tags for broken and disabled link states and move hidden link behavior into tags
goal: Test whether tags are the right mechanism for link behavior
status: complete
updated: 2026-10-08T14:22
---

- (decision) Hidden omits links from default listings while forwarding works. Broken flags a known destination problem while forwarding works. Disabled preserves the short URL but shows an explanation instead of forwarding.
- (direction) Use special-rule tags to unify state filtering through search such as #broken, avoid one toggle per property, and allow automation to track link states. Hidden keeps default omission and reduced opacity when revealed; broken uses an orange-red tint; disabled is greyed out. Users assign disabled; users or automation assign broken and hidden. Any newly detected broken tag should also cause hidden.
- (lock) Explicit #broken, #disabled, and #hidden searches reveal matching hidden links, including within hidden-only folders. Clearing the search restores the normal hidden-toggle setting. Ordinary text searches continue respecting Show hidden links.
- (decision) Revises earlier automation rule: automation must not assign hidden merely because a link becomes broken. Explicit #broken, #disabled, and #hidden searches reveal matching hidden links and hidden-only ancestor folders; clearing search restores the normal hidden setting. Ordinary text searches respect Show hidden links.
- (decision) No ownership metadata for broken tags for now. Automation may add or remove any broken tag based on its latest check, including a tag previously assigned manually.
- (decision) Disabled enforces a full stop across browser forwarding, Open, Download, and .sh execution. Proposed visual precedence of disabled over broken and continued short-URL copying have not yet been separately confirmed.
- (decision) Reserve hidden, broken, and disabled as exact case-insensitive special-rule tag names. #tag search matches a whole tag case-insensitively; ordinary text retains broad matching. Other tags remain descriptive.
- (decision) Clean replacement of hidden boolean: migrate existing hidden:true entries into the hidden tag while preserving other tags; retire the hidden property and reject it with a validation message directing maintainers to tag syntax. No ongoing legacy compatibility.
- (decision) Visual combination rules: disabled grey takes precedence over broken orange-red tint; hidden independently applies existing reduced opacity when revealed. State tags remain readable so color is not the only indicator.
- (lock) Hardened: replace hidden property with exact case-insensitive hidden/broken/disabled behavioral tags; use exact #tag searches with state searches revealing matching hidden entries; keep ordinary search visibility rules. Hidden preserves existing behavior, broken warns but forwards, disabled fully stops site-provided forwarding/open/download/script execution. Disabled grey overrides broken orange-red; hidden opacity is independent; tags remain readable. Clean migration rejects old hidden property. First implementation excludes automation; later automation may overwrite broken with no ownership tracking and must not hide links merely because they break. Detailed checker policy remains future work.
