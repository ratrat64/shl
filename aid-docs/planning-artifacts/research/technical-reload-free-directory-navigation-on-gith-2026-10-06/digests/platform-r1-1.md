# Platform and browser evidence, round 1

- Claim: GitHub Pages publishes static HTML/CSS/JavaScript and supports user-site roots and project-site prefixes. Source: GitHub, “What is GitHub Pages?”, undated, accessed 2026-10-06, https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages. Confidence: high; class: platform.
- Claim: Custom build workflows can deploy generated static files, including per-directory index pages. Source: GitHub, “Creating a GitHub Pages site”, undated, accessed 2026-10-06, https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site. Confidence: high; class: platform.
- Claim: Direct directory routes need an actual entry file, while missing paths require separate handling. Source: GitHub, “Troubleshooting 404 errors for GitHub Pages sites”, undated, accessed 2026-10-06, https://docs.github.com/en/pages/getting-started-with-github-pages/troubleshooting-404-errors-for-github-pages-sites. Confidence: high; class: platform.
- Claim: `pushState()` changes same-origin browser URL/history without immediately loading its URL; later browser navigation may load it. Source: MDN, “History: pushState() method”, updated 2025-06-23, accessed 2026-10-06, https://developer.mozilla.org/en-US/docs/Web/API/History/pushState. Confidence: high; class: browser compatibility.
- Claim: Fetch/content replacement and history traversal via `popstate` implement reload-free navigation; initial history entry also needs restoration. Source: MDN, “Working with the History API”, updated 2025-08-01, accessed 2026-10-06, https://developer.mozilla.org/en-US/docs/Web/API/History_API/Working_with_the_History_API; and “Window: popstate event”, updated 2026-07-28, accessed 2026-10-06, https://developer.mozilla.org/en-US/docs/Web/API/Window/popstate_event. Confidence: high; class: browser compatibility.
- Claim: `fetch()` resolves even on HTTP 404; check `response.ok`. Source: MDN, “Window: fetch() method”, updated 2025-12-16, accessed 2026-10-06, https://developer.mozilla.org/en-US/docs/Web/API/Window/fetch. Confidence: high; class: browser compatibility.
- Claim: HTML from `DOMParser` is an inert document, but transplanted markup can become active; do not treat untrusted markup as safe. Source: MDN, “DOMParser: parseFromString() method”, updated 2026-04-08, accessed 2026-10-06, https://developer.mozilla.org/en-US/docs/Web/API/DOMParser/parseFromString. Confidence: high; class: browser compatibility.
- Integration observations (not external research evidence): `src/build.mjs:33-49` emits static `index.html` for directory and redirect paths and public `links.json`; `src/pages.mjs:19-41` emits redirects; `src/pages.mjs:234-267` renders relative folder links and separately initialized search/copy scripts; `src/pages.mjs:310-361` supplies wrong-case fallback through 404. The copy handler only intercepts `a.code, a.destination` (`src/pages.mjs:200-216`), so folder links are the safe interception target. Replacing only `<main>` leaves header/footer links anchored to the old depth; rebase/refresh those links on navigation.
