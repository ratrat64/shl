# Runtime compatibility digest (accessed 2026-10-06)

- Claim: Deno 2.9 supports `node:` imports, package.json npm dependencies and Node globals, but package.json projects default to manual node_modules installation. Source: https://docs.deno.com/runtime/fundamentals/node/ ; publisher Deno; updated 2026-07-30; confidence high; class compatibility.
- Claim: Deno lists `node:test`, `node:child_process`, `node:fs/promises`, `node:path`, `node:url` as supported; `node:vm` is partial. Source: https://docs.deno.com/runtime/reference/node_apis/ ; publisher Deno; updated 2026-07-30; confidence medium; class compatibility.
- Claim: Deno defaults to no filesystem/subprocess access; build needs read/write, test harness also needs subprocess access. Source: https://docs.deno.com/runtime/fundamentals/security/ ; publisher Deno; updated 2026-06-17; confidence high; class permissions.
- Claim: Bun documents full `node:fs`, `node:path`, `node:url` and `node:vm` support, partial `node:child_process` and `node:test` support; lacks Node's `--test` CLI mode. Source: https://bun.com/docs/runtime/nodejs-compat ; publisher Bun; undated living documentation; confidence medium; class compatibility.
- Claim: Bun's `bun test` detects `.test.mjs` and accepts `--test-name-pattern`. Source: https://bun.com/docs/test ; publisher Bun; undated living documentation; confidence medium; class compatibility.
- Claim: Node 24 is LTS on 2026-10-06. Source: https://nodejs.org/en/about/previous-releases ; publisher OpenJS Foundation/Node.js; living schedule, latest release 2026-09-07; confidence high; class lifecycle.
- Local independent check: On repo commit 21017b6, Node 24 (`npx --yes node@24`), Deno 2.9.7 `deno run --no-lock -A build.mjs` and `deno test --no-lock -A test/build.test.mjs`, and Bun 1.4.2 (`npx --yes bun@latest`) `bun build.mjs` and `bun test ./test/build.test.mjs` each passed (26 links; 16/16 tests). Bun `test --test-name-pattern 404` and Deno `test --filter 404` each passed one test. `bun --test test/build.test.mjs` failed with "Cannot use test outside of the test runner". `deno run --no-config --no-lock -A build.mjs` could not resolve bare `yaml`; retaining package.json matters. `process.execPath` under Deno was the Deno binary. Source: local execution 2026-10-06; publisher independent repo experiment; class project-compatibility. Existing `npm ci` provided `node_modules`; neither clean install was tested.
