# CI and dependency digest (accessed 2026-10-06)

- Claim: Deno's GitHub CI documentation uses `denoland/setup-deno@v2`; `deno ci` requires a committed `deno.lock` and wipes existing node_modules before frozen install. Sources: https://docs.deno.com/runtime/reference/continuous_integration/ (updated 2026-06-14) and https://docs.deno.com/runtime/reference/cli/ci/ (updated 2026-05-20); publisher Deno; confidence high; class integration.
- Claim: Bun's official setup action is `oven-sh/setup-bun@v2`; `bun ci` uses a committed `bun.lock`, distinct from npm's lockfile. Sources: https://github.com/oven-sh/setup-bun and https://bun.com/docs/pm/cli/install ; publishers Bun/action maintainers; undated living docs; confidence high; class integration.
- Claim: Bun's `bun test` can run `node:test` in-process but Bun recommends `bun:test` for full Bun-specific runner features. Source: https://bun.com/docs/runtime/nodejs-compat ; publisher Bun; undated living docs; confidence medium; class compatibility.
- Local project frame (requirements, not outside research evidence): package.json declares only `yaml`; check.yml runs `npm ci`, `node --test test/build.test.mjs`, `node build.mjs`; deploy.yml uses npm and Node build; build.mjs is a Node-shebang wrapper for src/build.mjs; tests spawn process.execPath for each fixture and use node:vm; site is static Pages output with browser-side JS. Source: package.json, .github/workflows/{check,deploy}.yml, build.mjs, src/{build,links}.mjs, test/build.test.mjs, accessed 2026-10-06.
