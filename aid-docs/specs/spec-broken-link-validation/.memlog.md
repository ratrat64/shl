- (capability) CAP-1 intent: maintainers obtain bounded destination evaluations on a daily cadence or on demand. Success: a daily scheduled scan and full-map manual workflow dispatch check every eligible leaf including hidden/disabled; no external reachability gate is added to PR validation/build/deploy.
- (capability) CAP-2 intent: maintainers distinguish explicit disappearance from uncertain availability evidence. Success: matching 404/404 or 410/410 within one bounded evaluation means broken, a terminal 2xx means reachable, all remaining completed outcomes unknown and unvisited leaves skipped; attempts/status/error/time/SHA and coverage are reported.
- (capability) CAP-3 intent: the link map reflects decisive evidence without losing configured information. Success: broken adds canonical broken only if absent; reachable removes all exact trimmed case-insensitive instances even manual; unknown/skipped retain state. Nested JSON/YAML, comments, other fields/tags and hidden/disabled remain intact; repeated mutation is a no-op.
- (capability) CAP-4 intent: maintainers inspect automated source changes before ordinary static publication. Success: write mode commits only a changed source map to a guarded bot branch and maintains at most one open bot PR; valid required checks and human merge lead to existing Pages deployment; stale source/branch findings stop publication rather than overwrite.
- (capability) CAP-5 intent: maintainers evaluate checker behavior before enabling source updates. Success: report-only runs use the same scan/classification/diff calculation without committing/pushing/creating or updating PRs; representative trial evidence precedes scheduled source-edit proposals.
- (decision) Approved v1 meaning is conservative explicit HTTP disappearance, not all visitor outages. Latest check is the latest completed bounded evaluation with at most two attempts; no cross-run history/counters or durable cache. Unknown can retain stale broken and persistent DNS/TLS/5xx can remain untagged; make this limitation visible.
- (decision) Request destination URLs directly using GET, not generated shl URLs; follow HTTP redirects only, maximum 10 hops, preserve original URL and report final URL. Do not execute scripts, inspect page semantics, or interpret HTML/JS forwarding. Close/cancel response bodies after status; 2xx does not prove content, full download, or script correctness.
- (decision) Deduplicate identical full configured destination URLs within a run and fan out evidence to all matching codes; preserve query parameters and configured URL spelling. Use an honest checker User-Agent without destination credentials/cookies or browser impersonation.
- (decision) Starting bounds from approved recommendation: 15 seconds per attempt including HTTP redirect chain; at most two attempts; 45 seconds per destination evaluation including retries/waits; 10 redirect hops; 15-minute scan ceiling; four global requests, one per origin with short pacing. Tune only after measured report-only evidence; no SLA or measured capacity claim.
- (decision) On first 2xx finish reachable. Confirm first 404/410 with one retry. Retry temporary transport/5xx/429 once when budgets permit; retry success means reachable. No 2xx plus no two matching gone statuses means unknown, including mixed 404/410, 404/timeout, 401/403, unusual 4xx/3xx, TLS/DNS/timeout and redirect exhaustion. Exhausted in-progress evaluation is unknown; never-started is skipped.
- (decision) Use short jittered retry delay and per-origin pacing; honor valid Retry-After seconds or HTTP-date and origin cooldown, using bounded fallback for malformed/past values. If requested wait exceeds budget, defer origin requests; repeated 429 reduces work. All redirect hops participate in origin courtesy and limits.
- (decision) Normal budget-limited partial scan may propose only completed decisive results with coverage explicit; unknown/skipped do not mutate tags. Hard cancellation, parse/checker failure or invalid source means no candidate publication. Individual unavailable destinations are successful scan findings, not structural workflow failure; publication/internal failures fail workflow with evidence where available.
- (decision) Reuse shared validated source loading/traversal/state interpretation; keep shared raw snapshots readonly and edit a separate writable source document. Use installed yaml document APIs to preserve comments/order; JSON structural writes use existing formatting. Validate entire source before network work and validate changed output before publishing.
- (decision) Add broken to a URL-string leaf by expanding to a url/tags object only when needed; append lowercase broken only if no exact equivalent exists; remove all case variants on reachable without collapsing existing objects; remove newly empty tags property. Preserve every other field/tag value/order and destination spelling. Unknown retains original source representation; no formatted diff means no new commit/PR.
- (decision) Scan explicit main SHA and full destination; before publication refetch main and abort if changed. Use one checker concurrency group. Update PR only on a recognized bot-managed branch with expected head and no unexpected human commits; recompute from current main, never replay stale whole-file patches or unconditionally force-push. Stop/report if safe refresh cannot be made.
- (decision) Refresh evidence/desired PR diff on later scans. Withdraw unsupported pending suggestions or close an empty bot PR; this differs from clearing a live broken tag on unknown.
