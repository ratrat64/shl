- (insight) Explored 110 candidates across 11 passes using Morphological Analysis, Failure Analysis, Assumption Reversal, Build on What Works, Ship in 60 Minutes, Worst Possible Idea, and Decision Tree Mapping. Repeated techniques changed scope every ten ideas.
- (insight) Central synthesis: unknown belongs in scan evidence, not as another persisted link tag. The source stores only broken; incomplete or ambiguous evidence retains its previous state. This trades stale annotations for fewer false positives, and must be visible in the report.
- (insight) Latest check means latest completed bounded evaluation, which can contain two attempts; it does not mean every individual failed request flips a tag. This allows within-run confirmation with no cross-run history and no ownership tracking.
- (direction) Coach recommendation, not agreed requirement: Bundle A. Separate daily scan plus manual dispatch, check all leaves including hidden/disabled, GET destinations directly, bounded HTTP redirects, no script execution, report-only trial then bot PRs merged by a human.
- (direction) Proposed policy table: final 2xx => reachable/remove all exact case-insensitive broken tags immediately, even manual; two matching 404 or two matching 410 => broken/add canonical broken if absent; 404 then 200 => reachable; 404 then timeout/5xx or mixed 404/410 => unknown/unchanged; 401,403,429,5xx,DNS,TLS,timeout,redirect exhaustion,other non-2xx => unknown/unchanged; unvisited => skipped/unchanged.
- (insight) The recommended conservative policy detects explicit HTTP disappearance rather than all visitor outages. A permanently dead DNS name or repeated 503 can remain untagged indefinitely. Broader reachability-based broken semantics are a real alternative, but need agreed evidence and persistence rules; do not imply this narrow definition is already agreed.
- (direction) Proposed request defaults, not measured: 15-second total attempt deadline including HTTP redirect chain; at most two attempts; 45-second per-URL budget including waits; 10 redirect hops; 15-minute job ceiling; four global requests, one per origin with short pacing. Every redirect hop participates in origin courtesy. Retry-After respects seconds/date and remaining budget; unknown on excessive waits. Tune after report-only observations.
- (direction) No cross-run counters, durable health cache, ownership metadata, automatic hiding/disabling, content scraping, browser execution, per-domain rule engine, or downloaded script execution in proposed v1. Reports retain check time, source SHA, original/final URL, attempts/status/error category and coverage; 2xx proves only observed HTTP reachability, not useful content, complete download, or script correctness.
- (direction) Proposed publication lifecycle: scan exact main SHA; compute tag-only edits in the root source; preserve YAML comments via installed yaml document API and unrelated fields/tags; format source; validate/test/build; refetch main and abort if changed; commit source-map diff only on a bot task branch; open/update one clearly bot-managed PR; approve GITHUB_TOKEN-triggered PR workflows when required; human merge triggers existing push-to-main Deploy shl; confirm deployment completion. New scans refresh or withdraw obsolete PR suggestions; unexpected human commits or changed base stop publication rather than overwrite.
- (insight) Pending PR updates may require branch recreation/reconciliation after main advances; implement a safe stop/report first rather than unconditional force-push. Human merging an old PR is not proof of current destination state: show timestamp/SHA, refresh after destination edits and preferably before merging aged findings.
