# Working in this repository

## Git workflow
- The agent may write commit messages, push commits, and publish new branches for requested work. Use a task branch for changes intended for a pull request; do not push directly to `main`.

## Session startup
- At the start of a new session, before tackling the first task, read `README.md`, `aid-docs/planning-artifacts/ux-designs/ux-shortlink-2026-10-06/PRODUCT.md`, `aid-docs/planning-artifacts/ux-designs/ux-shortlink-2026-10-06/DESIGN.md`, and `package.json`. For UI tasks, also read the adjacent `EXPERIENCE.md`. Identify the relevant code paths, then briefly summarize how the project works and what you will inspect for the task.

## Branch and worktree workflow
- Before creating a new branch or worktree, update local `main` from `origin/main` with a fast-forward pull.
- Before making changes, create one task branch and a separate Git worktree; do the work and run checks there. Keep related features for the task together in that worktree.
- Preserve existing uncommitted work when consolidating changes from other worktrees.
- If `main` advances during feature work, check whether the feature needs changes to align with it; if so, make a plan for those changes before editing.
- For every task that changes repository files, after checks pass, commit and push the task branch and open a pull request against `main` without waiting for a separate request. Check the pull request for merge conflicts against the latest `main` and report its status.
- Check the pull request's merge status before finishing and again in later sessions. Once it is merged, remove its local worktree and delete its local task branch; do not discard uncommitted work.
- If resolving a conflict needs user input, report the blocker and stop; do not mark the feature ready.

## Git permissions
- The user authorizes agents to write commit messages, commit task changes, push commits, and publish new branches without asking again for each operation.

## Build and verification
- Use Bun 1.4.2 (the CI version) and `bun ci` to install the YAML parser. Launcher tests also require Bash.
- CI installs dependencies and applies `bun run format` (Prettier `--write`) before `bun test --timeout 30000 ./test/build.test.mjs` and `bun build.mjs`; deployment applies formatting before its build. Use `bun run format` locally and `bun run format:check` for a read-only check. Formatting is scoped to application build/source/test files, workflows, package metadata, and root link maps; exclude dist, vendor, and planning documents. Run from the repository root: build input and output paths are relative to the working directory. No lint or typecheck suite is configured.
- CI sets `SHL_REQUIRE_BROWSER=1` so rendered checks fail rather than skip without Chrome. Use the same mode for shared UI verification; set `CHROME_BIN` if the installed browser is not named `google-chrome`. An optional local run that skips Chrome is not visual proof.
- Focused routing checks: `bun test --test-name-pattern="404" ./test/build.test.mjs`. Tests build in temporary directories and execute generated scripts with simulated browser APIs; actual Pages 404 behavior needs a deployed browser smoke test.
- A successful build deletes and recreates `dist/`. Edit the templates in `src/pages.mjs`, not generated files; input validation lives in `src/links.mjs`, and `src/build.mjs` writes the site.
- Optional local preview: `bun run dev` builds and serves `dist/` with pinned `http-server`; restart it after editing links. Redirects use HTML meta refresh and JavaScript, not HTTP redirects; `curl -L` does not follow them.

## Link and routing constraints
- Exactly one of `links.json`, `links.yaml`, or `links.yml` must exist. Each accepts a URL string, a link object with `url`, optional `title`, and an optional `tags` array of nonblank strings, or a nonempty nested object for a directory. Exact trimmed case-insensitive `hidden`, `broken`, `disabled`, and `script` tags derive leaf states; raw public values remain intact. Reject every legacy `hidden` and `script` property with tags guidance before output deletion. All formats produce public `dist/links.json` for the browser-side 404 handler.
- Reject raw whitespace, commas, Unicode uppercase/titlecase and emoji anywhere in tags before deleting output, naming source/path/value and explicit maintainer renaming. Use Unicode Uppercase + Lt, Extended_Pictographic + Emoji_Presentation + Regional_Indicator + U+20E3; do not ban bare digits/#/*. Preserve valid lowercase/uncased international text, punctuation, NUL, raw order and public values. Never silently trim/lowercase/strip invalid names. Typed uppercase tokens still match known lowercase identities; defensive trimmed/case-insensitive recovery remains.
- Show tags exposes a fixed hidden-inclusive subtree catalog minus selections. Selected tags use AND plus one broad remaining-text substring. Only selected hidden/broken/disabled tags admit matching hidden leaves and ancestors; script alone does not. Commit known #tokens with whitespace/comma/Enter, consuming syntax once; retain unknown input with independent Tag not found feedback. Bare # matches nothing. Search enhances every nonempty subtree, including all-hidden pages. Cross-page mounts reset filters/error/picker/disclosures; same-page fragments retain them.
- Generate ALL tag inks directly from UTF-16 FNV-1a seed (2166136261, Math.imul(seed ^ charCode,16777619) >>> 0), including state labels: hue=(seed%3600)/10, saturation=55+((seed>>>16)%21), light lightness=20+((seed>>>24)%3), dark=80+((seed>>>24)%5). No finite/reserved color slots or storage. Renderer publishes lossless data-tag and generated --tag-light/--tag-dark once; selected chips clone metadata. Shared --tag-tone uses light-dark under root color-scheme and color-mix fill/borders. Keep separate row-state emphasis, neutral disabled non-tags and independent hidden opacity; verify ≥4.5:1 across full generated hue/bounds, current-map tags and all states on actual rest/hover tints/wash. Preserve selected-before-search (left desktop/above mobile), full-label scrolling, 50px rows, focus/count/native foundations.
- Disabled short URLs emit shared minimal explanations without forwarding/canonical destination/fallback. Recovery goes to the canonical short URL. Disabled destinations are selectable copy-only buttons without external href; both copies work and Open/Download are disabled buttons. Disabled script launchers print the specified explanation and exit 1 without downloading, temporary payloads, execution, or arguments. Destinations remain public and valid HTTP(S); disabling is not external access control. Broken warning colors yield to disabled grey; hidden opacity remains independent.
- `script` tag adds a `<code>.sh` Bash launcher. Launcher URLs require exact casing and no trailing slash; filename collisions with codes are rejected case-insensitively before output is removed.
- Every path segment must match `^[A-Za-z0-9][A-Za-z0-9._-]*$`. Reserved names and case-insensitive collisions are rejected among siblings, including generated filenames such as `index.html` and launcher `.sh` files. A directory cannot also be a redirect.
- Destination validation requires an absolute HTTP(S) URL parsed by `URL`; it does not check reachability. Validation completes before output is removed.
- Inline-script values need `scriptString`, not just `JSON.stringify`: HTML recognizes `</script>` inside JavaScript strings. Use `esc` for HTML contexts.
- Bash destinations need `shellString` for shell quoting. Enabled launchers download fully before execution, forward arguments and exit status, and clean up on exit. Tests use a stubbed `curl` and harmless payloads.
- Generated directories preserve code casing. Wrong-case requests rely on GitHub Pages serving `404.html`, which fetches the link map and matches the entire relative path case-insensitively, including directory pages.
- Routing must support both user-site roots and project-site prefixes (`/<repo>/`); no base-URL environment variable is needed. The homepage shows expandable nested directories, with browseable pages at each directory URL; use relative short-link paths and escape displayed values. The link map remains public.

## Deployment
- `.github/workflows/deploy.yml` checks, builds, and deploys on pushes to `main` or manual dispatch. Only `dist/` is uploaded; an optional root `CNAME` is copied there by the build.

## Shared UI ownership and consistency
- Before adding or changing UI, inspect and reuse the existing component, helper, or pattern. Extract repeated structure or behavior with the same responsibility; keep unique page content local.
- Render the shared site shell (header, navigation, theme control, and footer) through `src/layout.mjs`; pages supply content inside `<main>`. Reuse directory components in `src/directory.mjs` and native browser behavior in `src/assets/*.js`; do not duplicate them in page templates. HTML templates remain in `.mjs`; use `/* HTML */` to enable embedded formatting, preserving escapes and whitespace-sensitive code samples.
- Read `aid-docs/planning-artifacts/architecture/architecture-shortlink-2026-10-04/ARCHITECTURE-SPINE.md` before UI or shared-module changes; AD-7–AD-9 bind component ownership, styling, and lifecycle. Rewrite conflicting live instructions with any approved architecture amendment rather than keeping local exceptions.
- Every HTML page uses the shared document foundations. Links, nested directories, Guide, and 404 use the full shell; destination and legacy redirects and disabled explanations use the minimal variant. Keep forwarding, entry interpretation, traversal, and browser lifecycle logic in single-owner helpers; do not copy them between consumers.
- Keep shared styles and design tokens in `src/assets/site.css`. `src/styles.mjs` and `src/browser.mjs` load CSS/theme assets with `readFileSync` and module-relative URLs for embedded 404/minimal documents; the build copies native assets via stdlib. Scope unique content styles inside `<main>`; page/body selectors must not override shared chrome. Variants express component purpose or state, not page identity.
- Keep shared chrome visually identical across Links, nested directories, Guide, and 404 at equal theme/viewport, except active navigation state. Header/footer and Guide content sections are borderless; separate Guide sections with spacing and leave 2rem below its title. A local documented variant cannot override this contract.
- For shared UI changes, verify generated structure and real rendered appearance across those pages in light/dark themes and desktop/mobile layouts, including direct/native loads and applicable in-app navigation. Verify minimal redirect foundations and root/project-prefix 404 recovery too. Reuse existing checks; add focused regression checks for the changed responsibility.
- Do not treat shared markup as proof of visual consistency: body classes and CSS overrides can change the same component's appearance. Check those selectors and the design specifications when diagnosing differences.
